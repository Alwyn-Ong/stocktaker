# Changelog

## Unreleased

### Added
- Demo mode: a "Try Demo" button on the Landing screen loads a built-in sample inventory (`src/demo/demoData.ts`, including one item out of place each way) with no Google sign-in, master sheet or Drive. Session-only `demoMode` state plus `startDemo()`/`exitDemo()` in `inventoryStore`; load, scan, submit and unknown-barcode actions branch to local-only behaviour without touching AsyncStorage or Google APIs. New `DemoBanner` (with "Exit demo") on the picker and inventory screens, "Simulate item"/"Simulate unknown" buttons on the Scanner (with a placeholder when no camera permission), demo-mode Upload that writes the CSV to cache and opens the share sheet, and a Settings demo entry with "Exit demo".
- `docs/demo.gif` and `docs/demo.mp4`: screen recording of the demo flow, embedded in the README's Demo mode section, which now also notes that the recording skips Upload because it opens the share sheet.
- `README.md` with setup, Google Cloud/master-sheet requirements, and build instructions.
- `scripts/apply-branding.sh`: copies private artwork from the gitignored `branding/` directory over the placeholder icons in `assets/` (marking them `skip-worktree` so they can't be committed), with `--undo` to restore.

### Changed
- The "Try Demo" button is hidden unless the app is built with `ENABLE_DEMO=1` (exposed as `extra.demoEnabled` in `app.config.js`, listed in `.env.local.example`), so regular builds don't show it.
- Pressing Back on the Location Picker in demo mode now exits the demo (`LocationPickerScreen.handleBack` calls `exitDemo()` before `goBack()`), so Landing no longer shows the real-app screen while `demoMode` is still active.
- `ScannerScreen` requests camera permission once per mount instead of on every permission-state change, which re-prompted in a loop after a denial.
- Repo prepared for public release: `assets/` is no longer gitignored and holds generic placeholder icons (private artwork lives in `branding/`); `app.config.js` defaults `APP_NAME` to `Stocktaker`; `LICENSE` copyright updated; personal paths, email and Drive folder id removed from `ANDROID_DEV.md`/`RELEASE.md`; `.gitignore` now ignores `branding/`, `*.pptx` and `*:Zone.Identifier` files.

## 1.1.0 — 2026-07-09

### Added
- Release flow (`npm run release -- <version>`, see `RELEASE.md`): `scripts/release.sh` bumps the version in `package.json` and `android/app/build.gradle` (versionName + versionCode), cuts the changelog's Unreleased section into a dated version heading, generates a slide deck from `USER_MANUAL.md` (`scripts/generate-manual-pptx.mjs`, new `pptxgenjs` devDependency, also runnable alone via `npm run manual:pptx`), builds the release APK into `dist/Stocktaker.apk`, uploads the deck + APK to the Drive "Stock Taking > App > Latest" folder updating files in place so shared links survive (`scripts/upload-release-to-drive.mjs`, dependency-free, OAuth refresh-token auth with a one-time `scripts/get-drive-refresh-token.mjs` helper; new `GDRIVE_*` vars in `.env.local.example`), and commits + tags `v<version>` locally without pushing. `app.config.js` now reads `version` from `package.json` instead of hardcoding it.
- "Current Location" master sheet column (now a required header): `Item.currentLocation` optional field parsed by `fetchLocationsFromSheet` (blank cell → unset, meaning the item hasn't moved). `updateRows` writes it alongside "Updated At"/"Updated By" on submit, stamping each scanned row with the location it was scanned at. Exported `toLocationId` from `googleSheetsService` so screens/store can compare a raw location name against a location id.
- Cross-location scanning: a barcode belonging to another location is no longer treated as unknown — `ScannerScreen` looks the item up across all locations, records the scan (updating its current location to the scanned location), and shows an orange "✓ {name} — belongs in {home}" toast when scanned away from home. `inventoryStore.recordScan(barcode, locationId)` replaces `markDone`; a re-scan at a different location moves the single queued session scan rather than duplicating it, and a sheet-confirmed item is only a no-op when re-scanned at its current location.
- Combined per-location item list: `InventoryScreen` now lists every item that should be at the location plus every item currently there per "Current Location". Rows out of place are highlighted (amber background) via the new `ItemRow` `mismatch` prop — expected-but-elsewhere items show "⚠ Currently in: {location}", present-but-belongs-elsewhere items show "⚠ Belongs in: {location}".
- Unknown barcodes are now written to the sheet and cleared from local storage on Upload as well as Submit: new `inventoryStore.flushUnknownBarcodes(locationId)` (called by `InventoryScreen`'s Upload after the CSV export) shares a `submitLocationUnknowns` helper with `generateReport` that appends the location's session unknowns to the "Unknown Barcodes" tab, then drops all of that location's unknowns from persisted storage, state, and the session list.
- Printed report gained a "Current Location" column between "Description" and "Status".
- Uploaded CSV report: each location now gets a separate "Items currently here - belong elsewhere" section listing items from other locations whose "Current Location" points at the reported location, with a "Belongs In" column naming their home location. `serializeReport`/`exportReport` take a new optional `allLocations` parameter (passed by `InventoryScreen`) to find them; the section is omitted when empty.
- `googleSheetsService.appendUnknownBarcodes`: ensures an "Unknown Barcodes" tab exists in the master spreadsheet (creating it with a `Location, Barcode, Recorded At, Recorded By` header row if absent) and appends one row per unknown barcode on submit.
- Google Drive storage backend: connect/disconnect against one locked master Google Sheet (id configured via `GOOGLE_MASTER_SHEET_ID` in `.env.local`), and a Settings screen for choosing between local and Drive storage.
- `googleSheetsService`: reads/writes the master sheet via the Sheets API v4 REST endpoints (`spreadsheets.get`, `values.get`, `values:batchUpdate`), with header-name-driven column lookup.
- `googleAuthService` exposes the signed-in Google account's display name (from the native sign-in result) for use as the "Updated By" value.
- Submitting a report against the Drive backend stamps "Updated At"/"Updated By" columns on each scanned item's row in the master sheet, rather than overwriting the whole file.
- `Item.rowIndex`: optional field set by the Drive backend to track which sheet row an item came from.
- Unknown-barcode capture: barcodes scanned that aren't in the master list are persisted and listed in a separate "Unknown Barcodes" section of the generated report.
- Confirmation dialog when pressing the Android hardware back button on the Landing screen (app exit).
- `LandingScreen` (new root route): circular logo placeholder, "Continue" button, and Settings access.
- `LocationPickerScreen`: CSV import entry point with a dropdown-based location selector.
- `LocationDropdown` component: shared closed-row/modal location picker used by `LocationPickerScreen` and `InventoryScreen`.
- `ReportScreen`: review step before generating a report, listing only items and unknown barcodes scanned in the current session, with Submit, Print, and Cancel actions.
- `sessionScans`/`sessionUnknownBarcodes` in-memory store fields, appended to by `markDone`/`recordUnknownBarcode`, reset on every app launch.
- `src/utils/datetime.ts`: `formatGMT8()` helper formatting a `Date` as `YYYY-MM-DD HH:mm:ss (UTC+8)`, regardless of device timezone.
- `googleDriveService.uploadCsvToFolder`: multipart-uploads a CSV into a Drive folder via the Drive API v3 `files` upload endpoint, with the folder id configured via `GOOGLE_REPORT_FOLDER_ID` in `.env.local` (mirrored empty in `.env.local.example`, wired through `app.config.js` `extra.googleReportFolderId`). `googleAuthService` now also requests the full `drive` scope (needed to write into a hand-created folder, which `drive.file` cannot access).

### Changed
- Settings name field placeholder changed from `e.g. Warehouse 2` to `alias`.
- The location item-list report no longer opens a local share sheet; it now uploads the generated CSV straight to the configured Drive reports folder. The bottom-bar button is relabelled `Upload` (was `Print`), and a "Report uploaded" confirmation is shown on success. `csvService.exportReport` now serializes and uploads (file named `<location> - <timestamp>.csv`) instead of writing to the document directory and sharing.
- `csvService.serializeReport` footer now ends with a `Generated by:` line, the report's checked-by value (Google account name plus optional Settings alias), and the GMT+8 timestamp, in that order.
- Printed report gained an "Updated At" column between "Status" and "Checked By", carrying each item's master-sheet "Updated At" timestamp. The report now derives "Checked" status from this sheet-supplied timestamp (via the new optional `Item.updatedAt` field populated by `fetchLocationsFromSheet`) rather than the in-memory `done` flag, so a scanned-but-unsubmitted item stays "Unchecked" with no timestamp until its row is written to the master sheet. `inventoryStore.generateReport` now mirrors the submitted "Updated At"/"Updated By" onto the in-memory items so a Print immediately after Submit matches the sheet.
- Report generation is now per-location and inline on the item-list (Inventory) screen: the separate `ReportScreen` and `Report` route were removed, and `InventoryScreen`'s bottom bar now has three buttons — `Scan`, `Print`, and `Submit` — acting on the currently selected location only. Submit keeps you on the location (clearing only that location's queued scans/unknowns, leaving other locations queued) instead of bouncing to the Landing screen.
- `csvService.serializeReport` now groups the printed report by location: each location is a section headed by its name and a `Barcode, Item Name, Description, Status, Checked By` row, listing every item (both `Checked` and `Unchecked`) rather than only scanned ones. Each checked line carries its own "checked by" value (the master sheet's "Updated By", falling back to the report's `checkedBy` for items checked this session); the global "Checked by:" footer line was dropped, leaving just the GMT+8 timestamp. `InventoryScreen`'s Print passes only the current location and its unknown barcodes.
- `googleSheetsService.fetchLocationsFromSheet` now reads each row's "Updated By" cell into the new optional `Item.checkedBy` field, so the printed report can show who checked each item.
- `inventoryStore.generateReport(locationId)` now takes a location id and submits only that location's session scans (stamping "Updated At"/"Updated By") and unknown barcodes (appended to the dedicated "Unknown Barcodes" sheet), clearing only that location from the persisted session lists.
- `Item` dropped `quantity`/`scannedCount` in favor of a single `done` boolean; re-scanning an already-done item is now a no-op instead of incrementing a counter.
- Generated report now only includes scanned items; the `Quantity` and `Status` columns were removed.
- `csvService.parseCSV` no longer reads the `Quantity` column from the master CSV.
- Navigation flow changed from a single location-list root screen to `Landing → LocationPicker → Inventory ⇄ Scanner`, with `Report` reachable from `Inventory`.
- `InventoryScreen` header now shows an inline `LocationDropdown` for switching locations in place (no back navigation) instead of a static location name; the circular "Scan" FAB was replaced by a two-button bottom bar ("Scan" and "Finish / Generate Report").
- "Generate Report" no longer runs immediately from the location list; it now navigates to `ReportScreen`, whose Submit button calls the existing `generateReport()`.
- `ReportScreen`'s Submit failure alert now shows the specific error message instead of a generic failure string.
- `SettingsScreen`'s Drive section shows "Signed in as {name}" instead of an active-file label.
- Replaced `app.json` with `app.config.js`, which reads the Android `package` name and `extra.google*` values from gitignored `.env.local` (see `.env.local.example`) via Expo's built-in dotenv support, instead of hardcoding them in a committed file.
- `googleAuthService` now uses `@react-native-google-signin/google-signin` (native Android Credential Manager flow) instead of `expo-auth-session`'s browser-based authorization-code flow. Google's authorization server rejects custom-scheme `redirect_uri` values (e.g. `stocktaker://`) for "Android" type OAuth clients with `Error 400: invalid_request`, and Expo itself deprecated Google support in `expo-auth-session` as of SDK 49. The native library re-uses the same Android OAuth client (validated by package name + SHA-1, already configured) with no redirect URI involved.
- OAuth scope narrowed from `https://www.googleapis.com/auth/drive` to `https://www.googleapis.com/auth/spreadsheets`, matching the Sheets-only API surface actually used (also a lower Google verification tier: "sensitive" rather than "restricted").
- `app.config.js`: dropped the now-unused `scheme`/`GOOGLE_ANDROID_CLIENT_ID` config and the `expo-web-browser`/`expo-secure-store` plugins; added `ios.bundleIdentifier` (required by the new plugin's prebuild step) and the `@react-native-google-signin/google-signin` plugin.
- `generateReport()` now clears `sessionScans`/`sessionUnknownBarcodes` after a successful submit (either backend); previously they were never cleared until app restart, so the Report screen kept showing already-submitted items. Still preserved on a failed submit, so the user can retry without re-scanning.
- `inventoryStore.generateReport()`'s Drive "Updated At" stamp now uses `formatGMT8()` instead of `Date.toISOString()`.
- `SettingsScreen` no longer has an inline "Connect Google" button (that action moved to `LandingScreen`); it now shows an editable "Checked by" alias field (persisted via `setCheckedByAlias`) and, when signed in, a "Sign out" action.
- `LandingScreen` now drives the Google sign-in flow directly: shows a "Connect Google" button when signed out (replacing the always-enabled "Continue" button), and "Signed in as {name}" plus "Continue" once connected.
- `app.config.js` now reads `expo.name`/`expo.icon` from `APP_NAME`/`APP_ICON` env vars (defaults: `'Stocktaker'` / `./assets/icon.png`), and exposes `appName` via `extra` for runtime use. New keys added to `.env.local.example` (blank).
- `LandingScreen`'s title text and exit-confirmation alert now read the app name from `Constants.expoConfig.extra.appName` instead of a hardcoded `'Stocktaker'` string.
- `LandingScreen`'s logo `Image` now requires `assets/logo-override.png` (a committed generic placeholder, currently identical to `assets/icon.png`) instead of `assets/icon.png` directly, so a custom logo can be swapped in locally by overwriting that file's bytes without touching tracked source code. The override file's content is intentionally not customized in this commit.
- `csvService.serializeReport`/`exportReport` now take a `checkedBy` string: the scanned-items table is headed by an "Items Present" row, the unknown-barcode section is labeled "Unknown barcodes - not in master list", and a footer with "Checked by: {name}" plus a GMT+8 generated timestamp (`formatGMT8`) is appended.
- `ReportScreen`'s Print action now passes `checkedByAlias`/`displayName` through to `exportReport` as the report's `checkedBy` value.
- `App.tsx` wrapped in `SafeAreaProvider`; `InventoryScreen`'s and `ReportScreen`'s bottom button bars and `ScannerScreen`'s overlay now add `useSafeAreaInsets()` bottom (and, for the scanner's top bar, top) padding so the buttons clear Android's gesture nav bar.
- `USER_MANUAL.md`: end-user guide covering sign-in, location selection, scanning, report submission, and Settings.
- `AGENTS.md` Workflow section now requires `USER_MANUAL.md` to be kept up to date when user-facing behavior changes.
- `csvService.test.ts` and `inventoryStore.test.ts` rewritten to match the Sheets-backend implementation: removed `loadCSV` and `backend`-field coverage (both removed from the implementation in earlier changes), and added coverage for `serializeReport`'s new header/footer format, `hydrateSettings`, `loadInventory`, `setCheckedByAlias`, and the alias/display-name fallback paths in `generateReport`.
- `ReportScreen`'s Print failure alert now shows the specific error message instead of a generic failure string (matching the existing Submit failure alert).
- `sessionScans`/`sessionUnknownBarcodes` are now persisted to `AsyncStorage` (new `loadSessionScans`/`saveSessionScans`/`loadSessionUnknownBarcodes`/`saveSessionUnknownBarcodes` in `storageService`) instead of living only in memory, so they survive app restarts/reloads instead of silently dropping items still pending submission.
- `googleSheetsService.fetchLocationsFromSheet` now derives an item's `done` status from whether the master sheet row's "Updated At" cell is non-blank, instead of always returning `false`. The master sheet is now the source of truth for "checked" status: clearing a row's "Updated At" on the sheet, then reloading/refreshing, un-checks it locally. Removed the local-only `doneState`/`submittedKeys` persistence (`loadDoneState`/`saveDoneState`/`loadSubmittedState`/`saveSubmittedState`, `STORAGE_KEY`/`SUBMITTED_KEY`) that previously made "done" sticky forever regardless of the sheet's actual contents. `markDone` now optimistically marks an item done in memory while it's still queued in `sessionScans` (pending submission); `ScannerScreen` treats "Already scanned" as meaning confirmed on the sheet and not pending, otherwise it (re-)marks the item and queues/keeps it queued for submission.
- `InventoryScreen` gained a "↻ Refresh" header button that re-runs `loadInventory()` to resync the item list and done status against the master sheet on demand, surfacing any failure via an alert.
- The Settings "Checked by" field is renamed "Name (optional)" and gains a helper line explaining its effect. The value it holds (`checkedByAlias`) is no longer used in place of the Google account name; it's now appended in parentheses after it (e.g. "Jane Doe (Warehouse 2)"), via new `formatCheckedBy` (`src/utils/checkedBy.ts`), wherever a "checked by"/"updated by" name is written: the master sheet's "Updated By" column and the printed report's "Checked by:" line.
- `icon.png`, `android-icon-foreground.png`, `android-icon-background.png`, and `android-icon-monochrome.png` are now resized copies of `logo-override.png`'s current artwork, replacing the default Expo template icon. A native rebuild (not just a JS reload) is required for the change to show on a device.

### Removed
- `ReportScreen` and the `Report` navigation route: the report review step was folded into `InventoryScreen` as inline per-location `Print`/`Submit` buttons.
- "Qty: N" display from inventory item rows.
- `LocationsScreen` and its `FlatList` of `LocationCard` rows (superseded by `LandingScreen` + `LocationPickerScreen`).
- `googleDriveService.ts` and the Drive file browse/pick UI in `SettingsScreen` (superseded by `googleSheetsService` and the locked master sheet config). `driveFileId`/`driveFileName` removed from `Settings`.
- Local CSV import/export backend: `csvService.parseCSV`/`loadCSV`, the `DocumentPicker`-based file picker on `LocationPickerScreen`, and `Settings.backend`/`StorageBackend`. The master Google Sheet is now the app's only data source.
- All implemented entries from `changes.md`, including the four legacy `[DONE]` items that had been left in place across prior commits instead of being removed.
